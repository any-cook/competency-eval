# 成長ノート（力量評価システム）

社員が **毎月1回、自分の力量を自己評価** し、**半年に1度、自分の目標を決めて毎月その進み具合も記録** します。
半年の終わりに管理者が点数と目標の達成度をつけて **本人に公開** します。
結果は「レベル（🔰見習い → … → 👑エニクックになくてはならない存在）」の10段階として、本人の画面に見える形で育ちます（呼び名は変更可）。

- **月の自己評価は、その月のうちだけ**入力・提出できます。月がかわると前の月はさかのぼって入力できません（サーバーの時刻＝日本時間で制限）
- 出し忘れた月は「⚠️未提出」として記録に残ります

- 本人画面：`index.html`（ピンク系）／管理画面：`admin.html`（ティール系・「管理画面」バッジ付き）
- 部署（製造部・営業部・経理部）の評価表は、**登録メールアドレスで自動的に振り分け**られます
- 技術：GitHub Pages（静的サイト）＋ Firebase Authentication ＋ Cloud Firestore（ビルド不要）

## まず画面を試す（デモモード）
`config.js` の `apiKey` が空のあいだは、ブラウザ内のダミーデータで動きます（`?demo=1` を付けても可）。
デモでは `?demo=1&now=2026-12-10` のように「今日」を差し替えて、月がかわったときの動きを試せます（本番では無効）。
ローカルなら `python3 -m http.server` で開いて `http://localhost:8000/` へ。

## 導入手順（本番）

### 1. Firebase プロジェクトを**新しく**作る
> ⚠ タイムカードなど既存システムと**別のプロジェクト**にしてください。Firestoreのルールはプロジェクト単位のため、同じプロジェクトに反映すると既存システムのルールを上書きして壊します。

### 2. ログイン方法を有効化
Authentication →「始める」→ ログイン方法 →「メール/パスワード」を有効にする。
Authentication → 設定 → 承認済みドメインに、公開先のドメイン（例：`any-cook.github.io`）を追加。

### 3. Firestore を作成してルールを反映
Firestore Database →「データベースを作成」（本番モード・`asia-northeast1`）。
「ルール」タブに `firestore.rules` の内容を貼り付けて公開（または `firebase deploy --only firestore:rules`）。

### 4. `config.js` に設定を貼る
プロジェクトの設定 → マイアプリ → ウェブアプリを追加し、表示された `firebaseConfig` の値を `config.js` に貼る。

### 5. GitHub Pages で公開
このフォルダをGitHubにpushし、Settings → Pages → Branch を `main` / root にする。

### 6. 最初の管理者を作る（最初の1回だけ）
1. 公開された `index.html` を開き、「はじめての方」から**自分のメールアドレス**でアカウント作成 → 届いた確認メールのリンクを押す
2. Firestoreコンソールで、コレクション `staff` に **ドキュメントID＝メールアドレス（小文字）** で次を追加  
   `email`(string) = 同じメール ／ `name`(string) = 氏名 ／ `dept`(string) = 空 ／ `role`(string) = `admin` ／ `active`(boolean) = `true`
3. `admin.html` にログインできれば完了。以降は管理画面だけで操作できます

### 7. 社員を登録する
管理画面 →「社員名簿」で、メールアドレス・氏名・部署・権限を登録。
社員は `index.html` の「はじめての方」から**登録されたメールアドレス**でアカウントを作り、確認メールのリンクを押せば使えます。

**兼務の人**: 「社員名簿」の部署欄は複数チェックできます（「全部署」ボタンもあります）。複数の部署を選ぶと、その人の評価表は1つにまとまり、区分の前に「製造部／」のように部署名が付きます。月1回の自己評価と管理者評価は、まとめた表で行います。管理者も全部署を選べば、全部署の表で自己評価できます。

### 8. 評価期間（半年）を作る
管理画面 →「評価期間」で「2026年 下期（10月から）」などを作る（6か月・受付中で開始）。月が重なる期間は作れません。
期間が受付中のあいだ、社員は毎月の自己評価と半年の目標を入力できます。期間が終わったら「受付終了」に。

## 運用の流れ
**期間のはじめ**
1. 管理者が半年の期間を作る（受付中）
2. 社員が「🎯半年の目標」で目標を決めて確定する（5つまで。確定後は本人は変更不可。変えたいときは管理者が差し戻す）

**毎月（その月のうちに）**
3. 社員が「✏️今月の自己評価」で、力量評価＋目標の進み具合（0〜100%）を入力して提出する
   - 提出すると、その月は直せません
   - 月がかわったら、前の月は入力も提出もできません（管理者が差し戻せるのも「今月分」だけ）
4. 提出されると、管理画面の「評価一覧」の上に **📬新着のお知らせ**（返事待ちの一覧）が出て、タブにも件数が付きます
   - 本人が「今月のひとこと」などを書いていると「💬記載あり」が付き、先頭に並びます
   - 管理者が **💌ひとこと** を返す（300字まで。例文ボタンあり）か「返信なしで確認した」を押すと、お知らせから消えます
   - 返したひとことは、本人のマイページの上に **NEW** つきで届きます（開くと既読になり、管理画面にも「既読」と出ます）
   - ※メールやLINEでの通知はしません（サーバー側の仕組みが別に必要なため）。管理画面を開いたときのお知らせです

**半年の終わり**
5. 管理者が「評価一覧」から本人を開き、毎月の提出状況・目標の進み具合を見ながら、力量の点数と**目標の達成度**（まだこれから／途中まで／達成／期待以上）をつけて、総評を書く
6. 「本人に公開する」で、本人のマイページに表示される（公開前は見えません）

**いつでも（提案ボックス）**
- 社員は「💡提案ボックス」に、自己評価とは別に仕事・道具・職場・商品アイデア・評価制度への意見を書けます（名前つきで管理者に届きます）
- 管理者は「💡提案」タブで読み、状態（受付ずみ／検討中／採用／今後の課題／見送り）と返事を決めます。見送りのときは理由か感謝のひとことが必須です
- 「採用」にして「全員に紹介する」にチェックすると、全員のマイページに「🌟みんなの提案で実現したこと」として出ます
- 本人は、投稿ずみの内容を直せません（受付ずみの間は取り下げのみ可）。点数には関係しません

管理者評価と比べる自己評価は、初期状態では「最新の月」です（管理画面で月を選べます）。

## 評価基準と「仕上がり」（段階）
- 点数：1=×要支援／2=△補助／3=〇自立／4=◎熟練・指導／対象外（平均に含めない）
- 段階は**平均点**で決まります。標準は10段階の `level`。呼び名は `config.js` の `stageSet` で選べます

  | Lv | 平均点 | `level`（標準） |
  |---|---|---|
  | 1 | 〜1.29 | 🔰 見習い |
  | 2 | 1.3〜 | 🌱 新人 |
  | 3 | 1.6〜 | 🌿 準戦力 |
  | 4 | 1.9〜 | 🍀 戦力 |
  | 5 | 2.2〜 | 🌳 もうすぐ一人前 |
  | 6 | 2.5〜 | ⭐ 一人前 |
  | 7 | 2.8〜 | 🌟 頼れる存在 |
  | 8 | 3.1〜 | 💫 チームの柱 |
  | 9 | 3.4〜 | 🏅 みんなの先生 |
  | 10 | 3.7〜 | 👑 エニクックになくてはならない存在 |

  旧5段階（`curry` 仕上がり／`sodachi` 育ち／`akari` あかり）も選べます（しきい値は 1.5／2.25／2.85／3.5）。
  名前や文言を変えたいときは `scoring.js` の `SETS`、しきい値は `THRESHOLDS` を直します。
- バッジ：まいつき皆勤／つづけ上手（連続提出）／ぜんぶ入力／一人立ち／せんせい／ぐんぐん成長（先月より点数アップ）
- 目標の進み具合は本人が毎月つけ（0・25・50・75・100%）、半年末に管理者が1〜4で達成度をつけます。「仕上がり」には含まれません

## 評価項目を直すとき
`tools/competency-source.xlsx` を直して `npm run build:items`（= `python3 -I tools/build-items.py tools/competency-source.xlsx items-data.js`）で `items-data.js` を作り直します。
**項目のNo.を変えたり並べ替えたりすると、過去の評価とのひも付けがずれます。** 項目の追加は末尾の番号で。

## セキュリティの考え方
- メール確認済みのアカウントだけ使えます（他人のメールでなりすませません）
- 名簿に登録・有効なメールだけが評価データに触れられ、部署・権限は名簿（管理者のみ変更可）で決まります
- 本人が読み書きできるのは自分の分だけ。月の自己評価は**サーバー時刻の「今月」分だけ**書け、提出後は変更不可。目標は確定後、変更不可
- 月の判定は、書類の名前ではなく、サーバー時刻と照合した日付(`monthStart`)だけで決まります。端末の時計を変えても、さかのぼれません
- 管理者評価は「公開」するまで本人は読めません（画面の表示制御ではなく、Firestoreルールで遮断）
- ルールのテスト：`npm run test:rules`（Java と Firebase エミュレータが必要。さかのぼり不可・提出後の変更不可・他人のデータが読めないこと等を確認します）／採点ロジックのテスト：`npm test`
- リポジトリを**公開**にすると、評価項目の文言（`items-data.js`）が誰でも読めます。個人の評価データはFirestoreにのみ保存され、リポジトリには入りません。気になる場合は非公開リポジトリにしてください（GitHub Pagesの非公開公開はプランによります）
